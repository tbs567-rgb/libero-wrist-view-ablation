# 数据溯源手册：论文 / PPT 里每个数字是怎么跑出来的

> 定位：答辩与写作时的"数字字典"。每个数字都给出 **值 → 数据源 → 计算口径 → 复现命令**。
> 全部数字均由 `data_audit.py` 从原始 json **现算复核**（不照抄旧稿），最后复核：2026-10-13。
> 复现总入口：`D:\LIBERO`，解释器 `./.venv/Scripts/python.exe`（LIBERO venv，Py3.9 + torch 2.8 + mujoco 3.3.7）。

---

## 0. 一分钟版：一条完整的数字链路

```
官方 HDF5 演示（每任务 50 条人类演示，~98 步/条）
   ↓  load_official_hdf5()：4 帧堆叠 + 96×96 resize + 双视角 24 通道
训练（ResNet-18，600 epoch，~35 min/任务，单卡 6GB）  → low_resource_models/*.pt
   ↓  evaluate_all_inits()：该任务全部 50 个官方初始态，每态 1 局，每局 ≤300 步，256 渲染
成功率（成功局数 / 50）→ benchmark_results*.json / object_check_results.json
   ↓  同一批初始态上「单相机 vs 双相机」逐局配对
增益 Δ = 双 − 单（pp）→ 增益谱、全成绩表、条件规律 r
   ↓  另跑机制探针（逐局记录行为）
失败标签 / 阶段干预 / 瞄准误差 → stage_results.json
```

**一句话**：所有百分比都是"50 局里成功了几局"；所有 Δ 都是"同一批开局上双相机减单相机"；所有机制数字都是"探针逐局记录后聚合"。

## 3. 机制类数字（PPT 第 15、17、19 页）

**口径**：机制探针 `stage_analysis.py` 用同一批模型、同一批初始态重跑，逐局记录末端轨迹、物体抬升、到目标距离、夹爪开合、阶段切换，并给出失败标签（英文键：`grasp_fail` / `carry_fail` / `place_fail` / `no_grasp`；`None` = 成功）。

| 数字 | 值 | 怎么算的 |
|---|---|---|
| 抓取失败下降 | **−73.6%（≈−74%）** | Spatial 10 任务 × 50 局 = 500 局中 `grasp_fail` 局数：单 129 → 双 34 |
| 灾难性脱靶下降 | **−65.9%（≈−66%）** | 闭爪瞬间末端-物体距离 **> 8cm** 的局占比：13.4%（66/494）→ 4.6%（22/483） |
| 瞄准-增益相关 | **r = −0.723** | 10 个任务上「双相机闭爪距离均值 − 单相机」vs「该任务增益」的皮尔逊相关 |
| Object 链条断裂失败 | 单 **150/200（75%）** → 双 **17/200（8%）** | 失败标签 ∈ {`no_grasp`, `grasp_fail`, `carry_fail`} 的局数合计 |
| 逐任务链条失败 | t0 39→5、t3 20→4、t6 44→5、t9 47→3（每格 /50） | 同上，逐任务统计 |

> 注："抓取失败 −74%"与"链条断裂 75%→8%"是**两个不同口径**：前者是 Spatial 上"抓"这一类失败的变化率；后者是 Object 上"接近+抓+运输"三类失败的合计占比。

## 4. 开局级数字（PPT 第 16–17 页，n=700）

**口径**：14 任务 × 50 个官方初始态，提取物体/容器平面坐标与 `d_goal`（物体-容器距离），与探针的逐局成败配对；**零额外推理成本**（只跑环境恢复，不跑模型）。

| 数字 | 值 | 说明 |
|---|---|---|
| 样本 | **700 局**（14 × 50） | `init_pose_results.json` |
| 套件内救援相关 | Spatial **+0.003**、Object **+0.161** | r(d_goal, **救援率** = 双成且单败) |
| 混合 700 局表面相关 | **+0.245** | **Simpson 型混杂**：大距离样本几乎全部来自 Floor 场景的 Object；套件内分别算即归零 |
| 套件内成败相关（补充口径） | Spatial +0.059、Object −0.190、混合 −0.198 | r(d_goal, **单相机成败**)；与"救援率"口径不同，均为弱相关 |
| 任务内近/远半差异 | 均值 **8.9pp**，12/14 任务 <20pp | 按各任务 d_goal 中位数二分比较 |
| 任务级相关 | r(任务平均 d_goal, 单相机成功率) = **−0.352** | 显著弱于"单相机基线"的 −0.94 |

**结论**：开局几何不是核心变量 → "距离/可达性"的直觉解释被数据排除。

## 5. 因果干预数字（PPT 第 20 页）

**口径**：对双相机模型在特定**阶段**（approach / grasp / carry / place）干预腕部画面：
- `mask` = **冻结**（该阶段腕部画面替换为静止帧）；
- `mask-replay` = **重放**（替换为真实历史动态画面）。

判据：记基线 B、冻结 M、重放 R；冻结跌幅 ΔM = B − M，重放跌幅 ΔR = B − R。
- ΔR ≤ ΔM/3 → **伪影**（重放恢复 ≥2/3，说明跌幅只是"静止画面"这种分布外输入造成的）；
- ΔR > 2ΔM/3 → **真依赖**；其余为部分依赖。

**10 个有重放对照的格（现算）**：

| 任务·阶段 | 基线 B | 冻结 M（跌幅） | 重放 R（跌幅） | 判定 |
|---|---|---|---|---|
| t2 approach | 100 | 0（−100） | 96（−4） | 伪影 |
| t2 place | 100 | 38（−62） | 92（−8） | 伪影 |
| t7 approach | 58 | 0（−58） | 80（+22） | 伪影 |
| t7 grasp | 58 | 24（−34） | 72（+14） | 伪影 |
| t7 carry | 58 | 34（−24） | 58（0） | 伪影 |
| t7 place | 58 | 12（−46） | 28（−30） | 部分依赖 |
| t8 approach | 62 | 0（−62） | 64（+2） | 伪影 |
| t8 grasp | 62 | 48（−14） | 60（−2） | 伪影 |
| t8 place | 62 | 14（−48） | 16（−46） | **真依赖** |
| t9 approach | 94 | 0（−94） | 76（−18） | 伪影 |

**统计：8 伪影 / 1 部分依赖 / 1 真依赖**。
旧表述"7 格伪影 + 2 格真依赖"= 把部分恢复的 t7 place 也计入"存在真实依赖"；两种口径均已写入论文（以严格判据为主口径）。

## 6. 训练侧数字（PPT 第 10 页）

| 数字 | 值 | 说明 |
|---|---|---|
| 骨干 | ResNet-18（ImageNet 预训练） | `low_resource_resnet_fs.py: ResNetFSBC` |

## 7. 可靠性数字（PPT 第 9、21 页）

| 数字 | 值 | 说明 |
|---|---|---|
| 渲染协议影响 | 64/128/256 档差异可达**数十 pp** | 例：某任务 64 档 40%、128 档 78%、256 档 76% → 全部数字统一 **256** |

## 8. 复现命令速查

```bash
# ① 训练一个任务（双相机，默认 seed 7）
./.venv/Scripts/python.exe low_resource_official.py train \
  --h5 "datasets/libero_spatial/<任务>_demo.hdf5" --epochs 600 --dual-cam

# ② 评测 50 局（256 渲染，官方成功判定）
LIBERO_EVAL_CAM=256 ./.venv/Scripts/python.exe low_resource_official.py eval \
  --h5 "datasets/libero_spatial/<任务>_demo.hdf5" --episodes 50 --task-id <id> --dual-cam

# ③ 换种子（非 7 时模型存为 *_s<seed>_*.pt，不覆盖原模型）
./.venv/Scripts/python.exe low_resource_official.py train --h5 ... --epochs 600 --seed 1

# ④ 机制探针（逐局行为记录 + 失败标签）
./.venv/Scripts/python.exe stage_analysis.py

# ⑤ 开局级分析（n=700，零推理成本）
./.venv/Scripts/python.exe init_pose_analysis.py

# ⑥ 全部图表（fig1-6 / fig7-9，r 值现算复核）
./.venv/Scripts/python.exe make_figs.py && ./.venv/Scripts/python.exe make_figs_v2.py

# ⑦ 失败案例录像（单/双 × 外部/腕部 + 侧拼）
./.venv/Scripts/python.exe make_failure_videos.py

# ⑧ 数字总复核（本手册所有数值的出处）
./.venv/Scripts/python.exe data_audit.py
```

## 9. 常见追问与标准答法

| 追问 | 答法 |
|---|---|
| "成功率可信吗？只有 50 局" | 50 局是 LIBERO **官方协议**规定的数量；我们对关键结论做了多次独立重跑，并量化了 ±2 局的运行波动；结论建立在**跨 14 个任务的规律**上，不依赖单点。 |
| "数字对不上？" | 三种口径分工明确：**成绩表 = 256 评测批次**；**逐局机制 = 机制探针**；**跨批差异 = 运行波动**。探针与评测在 Spatial 上有 ±4~10pp 差异，已由双复跑实验查明是边界局翻转（见第 7 节）。 |
| "Object 只抽了 4 个任务？" | 是抽检（4/10），写作中明确标注为"抽检"，结论表述为"方向与量级复现"，不做整套件外推。 |
| "单种子吗？" | 主实验为单种子；多种子复现（8 单元）正在进行，完成后补均值 ± 标准差。 |
| "为什么 Object 与 Spatial 场景不同？" | 官方设计：Object = `LIBERO_Floor_Manipulation`（地面），Spatial = Tabletop（桌面）。已用 bddl 定义 + 官方 HDF5 状态恢复 + 渲染三重验证，不是环境装错。 |

## 10. 已知限制（主动声明项）

1. 主实验单种子（多种子补齐中）；Object 为 4/10 抽检；
2. 仅仿真（MuJoCo），无真机验证；
3. 融合方式为**朴素通道拼接**（刻意选择，保证消融干净），未与 cross-view attention 等方法对比；
4. 官方初始态的任务内距离跨度仅 3~7cm，开局级距离效应检验功效有限；
5. 不声称超越任何方法，定位为低资源约束下的系统实验与机制研究。
